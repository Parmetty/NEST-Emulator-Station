# Nest · 路线图

> 产品定义：一台“组装起来的虚拟主机”。把各世代主机的照片、游戏库、引擎、存档、手柄收进一个 Electron 外壳，
> 交互按“开一台主机”的逻辑走，而不是按“打开一个文件”的逻辑走。

## 边界（三条不做）

1. 不内置、不下载、不分发 ROM / BIOS / NAND / 密钥。
2. 不自研模拟器内核，只做宿主、调度、体验。
3. 不伪造系统界面：有真系统的才叫“系统模式”，没有的不假装。

## 架构决策速览

| 决策 | 结论 |
| --- | --- |
| 引擎形态 | 外部进程 + JSON 清单适配器（不做 libretro 内嵌） |
| 引擎分发 | 探测优先，缺失时给官方链接 + 校验，不随包分发 |
| 技术栈 | Electron + React + TypeScript，IPC 全量 zod 校验 |
| 数据层 | 先 JSON（原子写），后续可换 SQLite，接口不变 |
| 视觉 | 统一深色；首页四区（logo / 树状列表 / 全屏照片 / 信息卡） |
| 时间线 | 按发售年份排序，标尺跟随平台切换 |
| 交互 | 鼠标与键盘双通道；进入前弹「注意！」确认框 |

## 阶段与验收

### P0 · 骨架（已完成）

仓库、electron-vite、IPC 契约、JSON 库、引擎清单、进程监管、假引擎、单元测试、首页接真实数据。

验收：`--smoke` 自检通过；假引擎的启动 / 正常退出 / 崩溃 / 强杀四条路径全部有事件。

### P1 · 垂直切片（进行中）

扫描器 + GBA 全链路：导入文件夹 → 识别 .gba → 游戏库出现卡片 → 启动引擎 → 退出回主页 → 时长入账。

验收：一个空目录里放几个 `.gba` 文件，点“扫描”，卡片出现；双击启动，假引擎跑完，最近游玩更新。

### P2 · 多系统闭环

FC / SFC / N64 接入；固件校验；每游戏覆盖设置；存档备份。

验收：四个系统各自能扫描、启动、存档、还原。

### P3 · NGC + Wii

Dolphin 适配、记忆卡管理、NAND 导入向导与体检、Wii Menu 启动。

验收：导入 NAND 后能从应用内开机进 Wii Menu 并返回；NAND 缺失有分步指引。

### P4 · Wii U

Cemu 适配、MLC / keys 导入、Wii U Menu 启动、更新与 DLC 路径识别。

验收：同上标准；密钥缺失时给合规引导。

### P5 · 打磨与交付

手柄导航、封面抓取、CRT 滤镜、首次启动向导、NSIS + 便携版、自动更新。

验收：全新机器从安装到进游戏 ≤ 5 分钟，全程不碰配置文件。

### P6 · 预留口

xemu / Xenia / DuckStation / PCSX2 / RPSS3 / PPSSPP 的清单与空状态（默认隐藏）。

## 风险

- NAND / MLC 的 dump 成功率低 → 前置体检 + 分步指引，而不是“启动失败”。
- 引擎许可（Dolphin GPL、Snes9x 非商业、Cemu 闭源）→ 只探测、不随包分发。
- Electron 体积与内存 → 游戏运行时降 UI 频率、释放窗口。
